## Executive Overview

This document establishes the official **JCRC Diagnostic Test Menu** across all 9 operational laboratory sections. In the LabQMS architecture, every diagnostic assay listed here serves as a **Competency Anchor**. 

No Medical Laboratory Technologist or Analyst is authorized to perform testing, review Quality Control, or release clinical results without a documented, non-expired **Competency Assessment** specific to that test and its governing Standard Operating Procedure (SOP).

---

## The 6-Element Competency Assessment Model

In accordance with CAP and CLIA guidelines, competency for every test in this menu must be evaluated across six required elements:

1. **Direct Observation** of routine test performance (including specimen handling, preparation, and testing).
2. **Direct Monitoring** of result reporting and recording.
3. **Review** of intermediate test results, QC records, proficiency testing (PT) results, and maintenance logs.
4. **Direct Observation** of instrument maintenance and function checks.
5. **Assessment of Test Performance** through testing previously analyzed specimens, internal blind samples, or PT samples.
6. **Assessment of Problem-Solving Skills** via written/oral exams or case scenario evaluations.

## Technical Integration within LabQMS Architecture

### Database Schema Constraint Enforcement

In the PostgreSQL backend, result verification logic uses this relational integrity rule:

```sql
-- Schema rule preventing result release without validated competency
CREATE OR REPLACE FUNCTION verify_technologist_competency()
RETURNS TRIGGER AS $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM staff_competency sc
        JOIN lab_tests lt ON lt.id = NEW.test_id
        WHERE sc.user_id = NEW.technologist_id
          AND sc.sop_id = lt.primary_sop_id
          AND sc.status = 'Competent'
          AND sc.due_date >= CURRENT_DATE
    ) THEN
        RAISE EXCEPTION 'COMPLIANCE VIOLATION: Technologist % lacks active competency for Test Code % under SOP %',
             NEW.technologist_id, NEW.test_code, NEW.primary_sop_id;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

## Competency Documentation & Monitoring

This document is the primary reference for documenting and monitoring laboratory staff competencies across the JCRC test menu. Each listed test code and SOP must be linked to an auditable competency record before any technologist may perform, review, or release results.

### Competency Record Requirements

Every competency record in LabQMS must include:

- `technologist_name` / `user_id`
- `test_code`
- `sop_id`
- `assessment_date`
- `competency_status` (e.g. Competent, Needs Review, Suspended)
- `due_date`
- `assessment_type` (Direct Observation, Result Review, Maintenance, PT, Problem-Solving)
- `assessor_name`
- `assessment_notes`
- `next_review_date`
- `document_reference` (SOP number, checklist, exam copy)

### Competency Monitoring Matrix

| Monitoring Item | Description | Frequency | Responsible Party |
|---|---|---|---|
| Competency status review | Confirm active competency for each assigned test and SOP | Every 6 months or sooner | Section Head / QA |
| Expiry alert | Detect competency records expiring within 30 days | Daily automated check | QA / Lab Manager |
| Authorization hold | Block result release for staff lacking valid competency | Real-time at result entry | LabQMS application |
| Audit trail | Log every competency assessment and update event | Continuous | QA / IT |
| External audit package | Assemble test menu, SOP mapping, and competency evidence | Annual / CAP inspection | QA Lead |

### Competency Monitoring Workflow

1. Document the staff member and exact test code assessed.
2. Map the assessment to the governing SOP and laboratory section.
3. Complete the six competency elements required for that test.
4. Enter the assessment in LabQMS with status and due date.
5. Monitor expirations and missing competencies from the dashboard.
6. Restrict test authorization immediately if competency lapses.

### Dashboard & Reporting Requirements

LabQMS should provide at minimum these competency monitoring views:

- Active competency coverage by test, SOP, and section
- Upcoming expirations within 30/60/90 days
- Tests with missing or overdue competencies
- Staff competency assessment status and history
- Exceptions for results held due to competency gaps

### Audit and Escalation

- Maintain competency records for the employee lifecycle and audit retention.
- Log all failed assessments, performance issues, and corrective actions.
- Escalate non-compliance to the Section Head, Laboratory Director, and QA Manager.

### Integration Notes

- The LabQMS workflow must validate that the test performer has an active competency record matching the test code and SOP.
- Use a dedicated `staff_competency` table with relationships to `lab_tests`, `sops`, and `users`.
- Link competency assessments to the governing SOPs and related training documents.

## Summary

This test menu is also the foundation for competency enforcement and monitoring. Competency must be documented, reviewed, and audited with the same rigor as laboratory procedures, and the LabQMS system must enforce this policy in real time.
